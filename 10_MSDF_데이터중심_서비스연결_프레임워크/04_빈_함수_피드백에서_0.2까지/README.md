# 빈 함수 피드백에서 0.2까지 — 써 보는 사람의 눈으로 다시 보기

> **한 줄 요약**: 0.1.0을 공개하고 직접 설치해 써 보니 "UI가 안 열린다", "설치하자마자 오류가 난다", "기능이 `...`으로만 되어 있다"는 문제가 나왔습니다. 하나씩 원인을 다시 정의해 보니 대부분 **기능 부족이 아니라 "사용자가 보는 표면"의 문제**였고, 남은 로드맵은 실제 기능으로 채워 0.2.0으로 냈습니다.

---

## 1. 상황

- 0.1.0은 테스트 118개가 통과하고 설계 문서의 단계(1~10)를 모두 마친 상태였습니다.
- 그런데 다른 환경(Ubuntu, Windows)에서 처음부터 설치해 쓰면서 예상하지 못한 문제가 연달아 나왔습니다.

## 2. 문제와 원인 재정의

| 증상 | 처음 생각 | 실제 원인 | 조치 |
|---|---|---|---|
| 웹 UI가 열리지 않는다 | UI 빌드 문제 | ① 예시의 `run_local.py`는 **자기 프로세스 안에 엔진을 따로** 띄우고 끝나서 `msdf up`의 UI에 나타나지 않음 ② 원격 서버의 `127.0.0.1`은 그 서버 자신 | 엔진에 붙는 `run_services.py` 추가, `msdf up`이 SSH 터널 방법을 출력, 문서에 두 실행 방식의 차이 명시 |
| Windows에서 `msdf --version`부터 실패 | 인코딩 버그 | 경로에 한글이 있고 Python ≤ 3.12면 편집 가능 설치의 `.pth`를 cp949로 읽음 | 원인과 세 가지 해결책(UTF-8 모드 · 영문 경로 · 3.13+)을 문제 해결 표에 |
| 추가 묶음 없이 설치하면 import 오류 | 의존성 누락 | 핵심 기능도 `httpx`를 import하고 있었음 | 선택적 import, 필요한 순간에 "어떤 묶음을 설치하라"고 안내 |
| "기능이 `...`으로만 되어 있다" | 미구현 기능 | 코드의 `...`은 Protocol · overload 선언과 **본문 없는 서비스 함수**, 문서 예시의 생략 표시 | 아래 3절 |

## 3. `...`에서 0.2.0으로

코드의 `...`을 모두 찾아 분류했습니다. 빈 기능은 없었지만, 사용자는 `@service("search") def search(): ...` 같은 **의미 없는 빈 함수**와 문서 예시의 `def on_stats(stats): ...`를 보고 미완성이라고 느꼈습니다.

- **`service("search")` 한 줄 선언**을 추가하고, 예시와 문서를 모두 바꿨습니다. 문서 예시의 빈 본문은 실제 동작하는 코드로 채웠습니다.
- 내친김에 로드맵의 "다음에 할 것"을 실제 기능으로 채웠습니다.

| 0.1 로드맵 항목 | 0.2.0 |
|---|---|
| 버전이 Action 본문만 봄 (알려진 한계) | 프로젝트 안 도우미 코드까지 추적 |
| 엔진 · 서비스 인증 없음 | `--token` / `MSDF_TOKEN`, 서비스 · 엔진 · UI · CLI 모두 |
| UI 2초 폴링 | SSE 변경 신호 + 끊기면 폴링 |
| IAM은 YAML로만 | UI 권한 화면(편집 · 검증 · 저장 · 권한 시험) |
| DB 구조가 바뀌면 지우라고 안내 | 백업 후 자동 변환 |
| 큰 프로젝트 로딩 | 파일별 분석 캐시 |
| (없음) | 실행 취소, `msdf init/status/runs/cancel` |

- 각 기능은 테스트를 먼저 붙였습니다(118 → 139개). 토큰 인증은 **실제 서비스 프로세스를 띄워** 토큰 있는 서비스는 동작하고 없는 서비스는 거부되는지 확인했습니다.
- 새 화면은 실제 엔진에 붙여 스크린샷으로 검증했고, 그 과정에서 YAML 미리보기의 긴 줄이 화면을 가로로 밀어내는 레이아웃 버그를 잡았습니다.

## 4. 결과

- 처음 쓰는 사람은 `msdf init` → `msdf up` → 서비스 실행만으로 돌아가는 프로젝트를 얻습니다.
- 로드맵에서 "알려진 한계"였던 버전 문제가 사라졌고, 남은 항목(영어 메시지, `ctx.load/save`, 실행 중 단계 강제 중단 등)은 0.3 이후로 명확히 남겼습니다.

## 5. 배운 점

- **"기능이 없다"는 피드백은 "그렇게 보인다"는 뜻일 때가 많다.** 원인을 다시 정의하니 고칠 곳은 기능이 아니라 표면(빈 함수, 문서 예시, 실행 방식 안내)이었습니다.
- **처음부터 설치해 보는 것이 가장 좋은 테스트다.** 개발 환경에서 118개 테스트가 통과해도 다른 OS · 다른 경로 · 묶음 없는 설치에서는 다른 문제가 나옵니다.
- **알려진 한계는 문서보다 코드로 없앤다.** 문서에 적은 한계는 결국 누군가를 놀라게 합니다.
