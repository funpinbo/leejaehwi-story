# 프로젝트 개요 — MSDF (Micro Service Data Flow)

> 챗봇에 검색 · 크롤링 · 임베딩 · 요약 같은 기능이 붙을 때마다 **챗봇이 "무엇을 어떤 순서로 부르고, 결과를 어디에 두고, 실패하면 어떻게 할지"까지 떠안는** 문제가 있었습니다.
> 이 지휘 역할을 기능 밖으로 꺼내, **서비스는 결과물 이름만 요청하고 연결은 DAG가 정하는** 오픈소스 파이썬 프레임워크로 만들었습니다.

| 항목 | 내용 |
|---|---|
| 기간 · 형태 | 2026.11 ~ 진행 중 · **1인 개발** (설계 · 판단 · 검증은 직접, 구현은 AI 코딩 에이전트와 협업) |
| 공개 | [github.com/funpinbo/MSDF](https://github.com/funpinbo/MSDF) · MIT · 0.2.0 |
| 기술 | Python, FastAPI, SQLite(WAL, 단일 작성자 스레드), Pydantic v2, ast, Vue 3 · Vue Flow, SSE |

## 1. 배경 — 왜 만들었나

기존 ETL · ELT 도구(Airflow 등)는 **정해진 시간에 정해진 흐름을 도는 정적 · 결정적 파이프라인**에 맞춰져 있습니다.
그런데 챗봇 · 에이전트에서는 데이터를 추출하고 가공하는 일이 **사용자의 검색과 상호작용에 따라 실시간으로** 필요해집니다.

| 정적 파이프라인 | 챗봇에서 생기는 일 |
|---|---|
| 스케줄에 따라 전체 흐름을 돈다 | 질문마다 필요한 fetch · crawl · 가공이 다르다 |
| 흐름의 단위가 task | 관심사는 "어떤 데이터가 필요한가" |
| 같은 입력이면 다시 돌려도 됨 | 같은 질문이 반복되면 다시 계산할 이유가 없다 |

그래서 기능을 추가할 때마다 챗봇이 FETCH, CRAWL 같은 순서를 정하고 결과를 넘기는 **오케스트레이션을 직접 맡게 되었고**, 챗봇 코드가 계속 무거워졌습니다.
MSDF는 이 짐을 덜어 **기능들이 서로를 모르는 채로 데이터 변화에 따라 움직이게** 하고, 기능을 더하거나 뺄 때 **DAG 파일만 고치면 되게** 하려고 만들었습니다.

## 2. 문제

| 문제 | MSDF의 답 |
|---|---|
| 요청하는 쪽이 전체 순서를 안다 | `order("search_result")` — 결과물 **이름**만 요청, 연결은 DAG YAML |
| 같은 요청에 매번 다시 계산 | 데이터 ID를 입력 · 로직 버전 · 파라미터로 **결정적으로 계산** → 캐시 |
| 로직 하나를 고치면 전체 재실행 | 버전이 바뀐 단계부터만 다시, 앞 단계 결과는 재사용 |
| 누가 무슨 데이터를 어디로 보내도 되는지 모름 | IAM 규칙(order · flow · delete), 기본 거부 |
| 실패하면 어디서 깨졌는지 모름 | 단계별 상태 · 재시도 · lease, 데이터 계보(lineage), 웹 UI |

## 3. 성과

- **0.1.0 공개**: 엔진(`msdf up`) + 서비스 프로세스, Planner와 캐시, IAM, 삭제 · 보관(hot/cold), 웹 UI(실시간 맵 · n8n 스타일 DAG 편집기 · 로그)
- **0.2.0 공개**: 함수 없는 서비스 선언, 도우미 코드까지 반영하는 버전, 엔진 토큰, 실행 취소, IAM 편집 화면, SSE 실시간 갱신, DB 자동 변환, `msdf init/status/runs/cancel`
- 테스트 **118 → 139개**, 여러 프로세스를 실제로 띄우는 분산 테스트 포함 · ruff · mypy strict 통과
- LLM 없이 샘플 데이터로 도는 **챗봇 예시**(검색 → 임베딩 → 가공 → 챗봇), 한국어 · 영어 문서

## 4. 회고

- **"무엇을 만들지 않을지"가 먼저였습니다.** 서비스까지 만들려는 순간 범위가 무너져서, "서비스 사이 데이터 이동의 권한 · 실패 · 추적 계층이지 서비스 관리 시스템이 아니다"라는 한 문장을 기준으로 삼았습니다.
- 캐시와 부분 재계산은 **ID 설계 하나로** 해결됐습니다. Planner가 미리 계산한 ID와 저장소가 발급한 ID가 같아야 한다는 등식을 가장 먼저 테스트로 고정했습니다.
- 공개 후 실제 사용 피드백("UI가 안 열린다", "기능이 `...`으로만 되어 있다")이 설계 문서보다 많은 것을 고치게 했습니다.

## 5. 이전 프로젝트와의 연결

특정 도메인에서 떼어 **누구나 쓸 수 있는 프레임워크**로 일반화했습니다.
