# Content / Layout 분리 템플릿 엔진 — LLM은 JSON만, 문서는 코드가

> **한 줄 요약**: Word 템플릿 안에 `{{ part_number }}` 같은 placeholder를 두고, LLM은 **구조화된 JSON(내용)만** 생성하게 한 뒤, 템플릿 엔진이 **원본 XML · 스타일을 그대로 둔 채 값만 주입**하는 구조로 재설계했습니다.

---

## 1. 상황

- [01. 재생성 실패 분석](../01_LLM_문서재생성_실패분석)에서 "LLM이 문서 전체를 만드는 방식"은 레이아웃을 보장할 수 없다고 결론 내렸습니다.

## 2. 설계

```
[Word 템플릿]  ← 담당자가 Word에서 직접 양식을 만들고 {{ 키 }}만 넣음
     │
[LLM]  → {"part_number": "...", "manufacturer": "...", "test_summary": "..."}
     │
[스키마 검증]  Pydantic — 형식 틀리면 거부 / 재생성
     │
[템플릿 엔진]  python-docx로 run 단위 텍스트만 교체
     │          머리글 · 바닥글 · 표 · 폰트 · 정렬 · numbering · 이미지 · section · page break 보존
     ▼
[결과 문서]
```

| 역할 | 담당 | 성격 |
|---|---|---|
| 무엇을 쓸지 (내용) | LLM | 비결정적 → **스키마로 검증** |
| 어떻게 보일지 (형식) | Word 템플릿 + 코드 | 결정적 → **절대 LLM에 맡기지 않음** |

## 3. 구현하면서 만난 문제

| 문제 | 해결 |
|---|---|
| Word가 `{{ part_number }}`를 `{{ part_` + `number }}`처럼 **여러 run으로 쪼개 저장** | 문단 전체 텍스트에서 placeholder 위치를 찾고, 문자 위치 → run 매핑으로 **시작 run의 서식에 값을 넣고 나머지 조각만 삭제** |
| 표 · 머리글 · 바닥글 안의 placeholder | 본문 외에 표 셀, section별 header/footer 문단까지 순회 |
| 데이터에 없는 키가 조용히 빈칸이 됨 | 템플릿에 있는데 데이터에 없으면 **에러**로 중단 |
| LLM이 필드를 빼먹거나 형식을 틀림 | 부품번호 정규식, 최대 길이 등 **스키마 제약**으로 사전 차단 |

## 4. 결과

- **실제 계약서 및 PAD 양식에서 폰트, 정렬, numbering, 머리글/바닥글을 그대로 유지한 채 내용만 수정**할 수 있는 수준까지 도달
- 양식 변경은 담당자가 Word에서 직접 하면 되므로, 코드 수정 없이 양식을 바꿀 수 있음

## 5. 배운 점

- **책임을 나누면 각각을 검증할 수 있다.** 내용은 스키마로, 형식은 원본과의 비교로 검증합니다. 둘이 섞여 있을 때는 어느 쪽도 검증할 수 없었습니다.
- **현실의 데이터는 깔끔하지 않다.** run 분할처럼 "보이지 않는 구조"를 이해해야 실제 문서에서 동작합니다.
- 이 "원문(결정적)과 생성물(비결정적)을 분리"하는 관점이 ECSS 프로젝트의 `atomic_text` / `normalized_text` 분리로 이어졌습니다.

## 🧪 예제 코드 — `docx_template_engine.py`

placeholder가 **두 run으로 쪼개진 템플릿**을 일부러 만들고, 머리글 · 본문 · 표까지 렌더링합니다.
렌더링 전후의 형식 속성(스타일 · 폰트 · 크기 · 굵기)이 변하지 않았는지, 잘못된 LLM 출력이 스키마에서 거부되는지 확인합니다.

```bash
pip install python-docx pydantic
python docx_template_engine.py
```

```
=== 렌더링 결과 ===
머리글: PAD · PN-2026-0412
[Normal] 1. 부품 정보
[List Number] 부품 번호: PN-2026-0412
[List Number] 제조사: ACME Space Components
적용 규격 | ESCC 9000 (예시)
시험 요약 | 열진공 시험 및 진동 시험 통과, 비정상 항목 없음

형식 속성(스타일·폰트·크기·굵기) 변화: 없음 ✅
남은 placeholder: 없음 ✅

=== 스키마가 막아주는 잘못된 LLM 출력 ===
거부: 3개 오류 (부품번호 형식, 누락 필드)
```

## 🎤 면접에서 이렇게 말한다

> "LLM이 문서를 만드는 것과 내용을 만드는 것을 분리했습니다. Word 템플릿에 placeholder를 두고 LLM은 JSON만 생성하게 한 뒤, 템플릿 엔진이 원본 XML과 스타일은 건드리지 않고 값만 주입합니다. Word가 placeholder를 여러 run으로 쪼개 저장하는 문제도 문자 위치를 run에 매핑하는 방식으로 해결해서, 실제 PAD와 계약서 양식을 그대로 유지할 수 있었습니다."
