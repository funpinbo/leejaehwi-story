# 멱등 배치와 상태 분리 — "조용한 좌초" 사고에서 배운 것

> **한 줄 요약**: 사내 파일 서버 문서를 매시간 스캔 → 매시간 임베딩하는 배치를 만들면서, **파일 자체의 상태(`status`)와 RAG 반영 상태(`rag_status`)를 서로 다른 생명주기로 분리**했습니다. 그런데 삭제됐던 파일을 복원할 때 `rag_status` 초기화를 빠뜨려 **수백 건이 임베딩되지 않은 채 좌초**됐고, 이후 "상태를 되돌릴 때는 연계 상태도 함께 리셋한다"를 개발 표준에 넣었습니다.

---

## 1. 상황

| 배치 | 주기 | 하는 일 |
|---|---|---|
| scan | 매시 00분 | 사내 파일 서버를 돌며 파일을 발견 · 변경 감지 → 자산 원장(file_asset) 갱신 |
| embed | 매시 15분 | ① 삭제 전파 ② `PENDING` 문서 추출 · 청킹 · 임베딩 → chatbot에 전송 |
| retry | 매시 30분 | 실패 자산 재시도 |
| backup | 매일 | DB 전체 덤프 → 읽기 검증 → 사내 파일 서버 업로드, 30일 보관 |

## 2. 설계 판단

| 결정 | 이유 |
|---|---|
| **`status`와 `rag_status` 분리** | "파일이 원장에 정상 등록됐는가"와 "RAG에 반영됐는가"는 실패 원인도 재시도 주체도 다름 |
| `status`: DISCOVERED → REGISTERED / FAILED → (3회 초과) **QUARANTINED** / **MISSING** | 계속 실패하는 파일이 매 배치를 잡아먹지 않게 격리 |
| `rag_status`: PENDING → EMBEDDED / SKIPPED / FAILED | SKIPPED(20MB 초과 · 미지원 형식)는 RAG 쪽에만 있는 개념 |
| **mtime + size가 같으면 다운로드 · 해시 생략** | 수만 개 파일을 매시간 다시 받지 않음 |
| 해시: 512MB 이하 전체 SHA-256, 초과 시 **앞뒤 1MB 부분 해시** | 대용량 파일에서 스캔 시간 상한 |
| 업로드 중(60초 이내 수정) 파일은 건너뜀 | 반쯤 복사된 파일을 등록하지 않음 |
| **삭제 전파**: 사내 파일 서버에서 사라진 파일 → chatbot에 문서 단위 삭제 요청 | 지워진 문서가 계속 답변 근거로 나오는 것 방지 |
| 문서 ID = 파일 고유 ID, 청크는 **문서 단위 통째 교체** | 재처리해도 결과가 같은 **멱등** 작업 |
| 1회 처리량 축소 | 실행 제한시간(55분) 안에 끝나 다음 주기와 겹치지 않게 |
| 디렉터리 mtime으로 하위 탐색 생략 — **일부러 미채택** | 하위 변경이 상위 디렉터리 mtime에 전파되지 않아 누락 위험 |

## 3. 사고 — 조용한 좌초

```
파일 삭제     → status=MISSING, deleted_at 기록, rag_status=EMBEDDED → 삭제 전파 → (chatbot에서 청크 제거)
파일 복원     → status=REGISTERED, deleted_at=NULL           ← 여기서 rag_status를 PENDING으로 안 돌림
다음 embed    → rag_status=EMBEDDED 이므로 "이미 처리됨"으로 건너뜀
결과          → 원장에는 정상, RAG에는 없음. 에러 로그 0건
```

**원인**: 두 상태를 분리한 것은 옳았지만, **한쪽을 되돌릴 때 다른 쪽과의 관계를 정의하지 않았습니다.**

**조치**
1. 복원(RESTORED) 시 `rag_status = PENDING`으로 함께 리셋
2. 좌초 건 일괄 재처리
3. 개발 표준(스케줄링 규칙)에 "상태 복원을 추가할 때는 연계 상태값도 리셋하는지 확인" 추가
4. 정합성 점검: `status=REGISTERED AND deleted_at IS NULL AND rag_status=EMBEDDED`인데 RAG에 청크가 없는 문서 → 경보

## 4. 배운 점

- **상태를 나누면 상태 간 전이 규칙도 함께 설계해야 한다.** 분리는 시작이고, "A가 바뀌면 B는?"을 표로 만들어야 끝납니다.
- **조용한 불일치는 정합성 쿼리로만 잡힌다.** 에러가 나지 않는 버그는 "원장과 결과가 일치하는가"를 주기적으로 검사해야 보입니다.
- **배치는 멱등 · 항목 단위 실패 격리 · 실행 시간 상한** 세 가지를 먼저 정합니다. 처리량은 그다음입니다.
