# 가짜 유사도 점수 버그 — "점수 없음"을 1.0으로 표현하면 생기는 일

> **한 줄 요약**: 근거마다 유사도 점수를 붙여 상위 N개만 답변에 넣는데, 유사도 개념이 없는 근거(웹 일반 검색, SQL · 규칙 카탈로그 · 그래프 조회)에 "코드를 단순하게 하려고" **상수 `score=1.0`** 을 찍고 있었습니다. 진짜 코사인 유사도는 거의 항상 1.0 미만이라, **가짜 1.0이 상한에서 항상 이겨 진짜 관련 근거를 밀어냈습니다.** "점수가 없다"를 **키 자체가 없는 상태**로 바꿔 해결했습니다.

---

## 1. 상황

- 기술 질문의 근거는 여러 소스에서 섞여 들어옵니다.

| 소스 | 유사도 점수 |
|---|---|
| 내부 코퍼스 벡터 검색 · 승인된 답변 캐시 · 승인된 외부 참조 | 있음 — 진짜 코사인 유사도 (보통 0.6~0.9) |
| 웹 일반 검색 · SQL 조회 · 규칙 카탈로그 매치 · 그래프 구조화 조회 | 없음 — 개념 자체가 없음 |

- 답변 프롬프트 길이를 제한하려고 **점수 상위 `MAX_TOTAL_EVIDENCE`개**만 넣습니다.

## 2. 문제

```python
evidence.append({"source_type": "sql", "snippet": ..., "score": 1.0})   # "랭킹 코드를 단순하게"
```

- 벡터 근거(0.83, 0.79 …)와 섞이면 **가짜 1.0이 항상 1등**
- 벡터 근거와 다른 소스가 섞이는 질문(= 대부분의 질문)에서, 정작 가장 관련 있는 벡터 근거가 상한에서 잘림
- 에러는 없고, 답변 품질만 조용히 떨어짐

## 3. 해결

| 이전 | 이후 |
|---|---|
| `score: float` (항상 있음, 없으면 1.0) | `score: NotRequired[float]` — **진짜 유사도가 있는 소스만** 채움 |
| 모든 근거를 점수순 정렬 → 상한 | ① Task 태그 근거 · ② 점수 없는 근거는 **상한에서 제외해 전부 보존** ③ **점수 있는 근거만** 점수순 정렬 후 상한 |

```python
tagged   = [ev for ev in evidence if ev.get("task_name")]
rest     = [ev for ev in evidence if not ev.get("task_name")]
scored   = sorted((ev for ev in rest if "score" in ev), key=lambda ev: -ev["score"])
unscored = [ev for ev in rest if "score" not in ev]
return [*tagged, *unscored, *scored[:MAX_TOTAL_EVIDENCE]]
```

- 점수 없는 근거는 애초에 "유사도 랭킹"의 대상이 아니므로, 특정 하위 Task용으로 태그된 근거에 이미 적용하던 것과 **같은 처리**(상한 면제)를 적용
- PDF 청크 소스에서도 정렬에만 점수를 쓰고 Evidence를 만들 때 1.0을 다시 찍던 곳을 함께 수정

## 4. 배운 점

- **"없음"을 가짜 값(sentinel)으로 표현하지 않는다.** 1.0, 0, -1 같은 값은 비교 · 정렬에 그대로 참여해서 의미를 왜곡합니다. 없으면 없는 상태(키 없음, `None`, 별도 타입)로 둡니다.
- **서로 다른 척도는 섞어서 정렬하지 않는다.** 하이브리드 검색에서 BM25와 벡터 점수를 점수 대신 순위(RRF)로 합치는 이유와 같은 문제입니다.
- **조용한 품질 저하는 분석 문서로 남긴다.** 이 건은 별도의 갭 분석 문서로 원인 · 영향 범위 · 수정 범위를 정리한 뒤 고쳤습니다.
