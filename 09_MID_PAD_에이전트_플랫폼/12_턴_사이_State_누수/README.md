# 턴 사이 State 누수 — 체크포인터가 기억하는 "지난 턴의 값"

> **한 줄 요약**: LangGraph 대화 state가 커지는 문제를 조사해 보니, 한 턴 안에서는 키가 덮어쓰여 커지지 않았지만 **턴과 턴 사이**에서 문제가 있었습니다. 이전 턴의 라우팅이 설정한 필드를 이번 턴의 다른 경로가 건드리지 않으면, 체크포인터가 그 **낡은 값을 그대로 이어받았습니다.** 실제 누수 2건을 찾아 고쳤고, 해법은 "지워줄 노드가 돌았기를 기대"하지 않고 **턴 시작 시점에 리셋할 필드를 명시**하는 것이었습니다.

---

## 1. 상황

- 일반 채팅은 LangGraph + Postgres 체크포인터로 대화 단위(`thread_id`) state를 이어갑니다.
- state는 reducer 없는 평평한 `TypedDict` — 노드가 반환한 키는 그 값을 **덮어씁니다.**
- 질문 분야(기술 / 사내 정책 / 일반 / 사내 과제)에 따라 **턴마다 다른 노드 경로**를 탑니다.

## 2. 조사 — 어디서 커지는가

| 가설 | 결과 |
|---|---|
| 한 턴 안에서 노드를 지날수록 state가 누적된다 | ❌ reducer가 없으니 덮어쓰기 — 구조적으로 무한히 커지지 않음 |
| **턴을 가로질러** 이전 값이 남는다 | ✅ 체크포인터의 정상 동작: 이번 턴에 아무도 안 쓴 키는 지난 값 유지 |

## 3. 실제로 발견한 누수 2건

| # | 누수 | 증상 |
|---|---|---|
| 1 | 이전 턴(특정 부품 질문)의 **부품 식별 결과** | 다음 턴의 무관한 질문(예: 사내 정책) 답변 **메타데이터에 그대로 남음** |
| 2 | 이전 턴에서 감지된 **부품 변형(variant) 경고** | 다음 턴 research가 아무 변형도 못 찾았는데 **답변 프롬프트에 무조건 덧붙음** |

공통 원인: 그 필드를 비워 주는 노드는 **기술 질문 경로에만** 있었고, 다른 경로를 탄 턴에서는 그 노드가 돌지 않았습니다.

## 4. 해결

```
이전: "그 필드를 지워주는 노드가 이번 턴에도 돌았겠지"에 의존
이후: 턴 시작 노드에서 '턴 범위 필드' 목록을 명시적으로 초기화
      (대화 이력 · 누적 요약처럼 턴을 넘어 유지해야 하는 필드는 목록에서 제외)
```

- research의 evidence tree 상태도 **매 턴 새로 생성**하도록 명시 (이전 턴 트리가 섞이지 않게)
- 공유 state · evidence 타입을 바꿀 때는 **저장 · 조회 · 관리 API를 포함해 저장소 전체 소비자를 검색**하는 것을 개발 표준에 추가 (공유 TypedDict 계약 변경이 모듈 경계 밖까지 영향을 준 횡단 버그 경험)

## 5. 배운 점

- **state는 "무엇이 이번 턴 것이고 무엇이 대화 전체 것인가"를 나눠 설계해야 한다.** 이 구분이 없으면 체크포인터는 모든 것을 대화 전체 것으로 취급합니다.
- **"누군가 지워주겠지"는 경로가 하나일 때만 성립한다.** 분기가 생기면 초기화는 분기 앞으로 끌어올립니다.
- **증상(커진다)과 원인(남는다)을 구분한다.** "state가 커진다"는 보고를 그대로 믿었다면 reducer를 추가하는 엉뚱한 수정을 했을 것입니다.

---

## 🧪 예제 코드 — `turn_state_leak.py`

체크포인터 동작(이번 턴에 안 쓴 키는 이전 값 유지)을 흉내 내고, 기술 질문 → 사내 정책 질문 순서로 두 턴을 실행합니다.
`--bug`로 실행하면 이전 부품 식별 · 변형 경고가 다음 턴 답변에 새어 나오고, 기본 실행은 턴 시작 리셋으로 막힙니다.

```bash
python turn_state_leak.py        # 수정 후
python turn_state_leak.py --bug  # 누수 재현
```
