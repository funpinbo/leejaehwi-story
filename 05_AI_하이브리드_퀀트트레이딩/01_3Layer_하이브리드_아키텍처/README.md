# 3-Layer 하이브리드 아키텍처 — 숫자는 모델이, 맥락은 LLM이

> **한 줄 요약**: 정형 시계열 예측(Layer 1), 뉴스를 읽는 4개 페르소나 LLM 에이전트(Layer 2), 과거 사건의 영향력으로 가중치를 조정하는 메타 러너(Layer 3)로 역할을 나누고, 결과를 "예측 이동폭의 20%에서 진입, 60%에서 청산"하는 매매 계획으로 바꿨습니다.

---

## 1. 상황

- 목표는 **정형 + 비정형 데이터를 융합**해 사람 개입 없이 매매 시그널을 만들고 실행까지 하는 것.
- 하지만 LLM 하나에 "이 종목 살까?"를 묻는 구조는 **수치 예측에 약하고 재현성이 낮습니다.**

## 2. 설계 판단 — 역할 분리

| Layer | 역할 | 왜 이 구성인가 |
|---|---|---|
| **1. Baseline Models** | BSTS + CatBoost + PatchTST → Unified Return, 평균회귀 확률, 글로벌 매크로 시그널 | 숫자 예측은 통계·ML 모델이 LLM보다 안정적. 서로 다른 성격의 모델을 결합해 한 모델의 편향을 줄임 |
| **2. Agent LLM** | Global · Economy · Industry · Company 4개 페르소나가 뉴스를 분석, **최대 3라운드 Agentic Feedback Loop**로 판단 정교화 | 뉴스의 "맥락"은 LLM이 강함. 관점을 나눠야 한쪽 뉴스에 쏠리지 않음 |
| **3. Meta-Learner** | 클러스터 영향력 분석 결과를 FAISS RAG로 저장 → Layer 1 가중치 조정 (구현 진행 중) | "이런 유형의 뉴스 뒤에는 어떤 모델이 잘 맞았나"를 학습 |

**운영 원칙**: 로컬 LLM(Ollama KANANA 1.5 8B)이 기본, 클라우드(Gemini 2.5 Flash)는 **장애 시 폴백**으로만. → API 비용 0, 매매 전략·포지션 정보 외부 유출 없음.

## 3. 실행 파이프라인

```
22:00  야간 스크리닝  : 약 460종목 유니버스 → Layer 1·2 → 매매 Plan 생성
09:06  익일 자동 주문 : KIS REST API
장중   5분 주기 재판단 : 보유 종목 SELL / HOLD / BUY_MORE (→ 05 ReAct 재판단)
```

## 4. 전략 — 조기 진입 · 조기 청산

- 예측 이동폭 전체를 먹으려 하지 않고, **이동폭의 20% 지점에서 진입, 60% 지점에서 청산**합니다.
- 예측이 "방향은 맞고 크기는 틀리는" 경우가 많다는 점을 반영해, **확률적 우위를 반복적으로 확보**하는 쪽을 택했습니다.

## 5. 결과

- 37일간 운영하며 298종목 · 1,157건의 판단 이력을 축적 (→ RAG 데이터로 재활용)
- 모의투자 백테스트 승률 약 30% — 아직 실전 전환 전 검증 단계라는 점을 분명히 합니다.

## 6. 배운 점

- **LLM에게 모든 걸 맡기지 않는다.** 숫자는 숫자 모델이, 맥락 해석은 LLM이 맡도록 역할을 나누니 각 Layer를 따로 검증·교체할 수 있었습니다.
- **전략도 모델의 한계에 맞춰 설계한다.** 예측 크기의 불확실성을 진입·청산 비율로 흡수했습니다.
