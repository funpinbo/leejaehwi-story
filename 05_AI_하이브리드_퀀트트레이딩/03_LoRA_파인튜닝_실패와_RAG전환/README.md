# LoRA 파인튜닝 실패와 RAG 전환 — "학습시키면 나아진다"는 가정 버리기

> **한 줄 요약**: 3주치 데이터로 EXAONE을 LoRA 파인튜닝했더니 출력 형식이 깨져 파싱 성공률이 20% 미만이 됐고, 오히려 **파인튜닝 없이 KANANA 1.5 8B를 그대로 쓰니 90%+** 로 올랐습니다. 이후 학습 대신 **과거 매매 판단 이력을 few-shot으로 넣는 RAG**로 전환했습니다.

---

## 1. 상황

- Layer 2 에이전트는 뉴스를 읽고 **정해진 JSON 형식**(`decision`, `confidence`, `reason`)으로 판단을 내야 합니다. 파싱이 실패하면 그 종목은 판단이 없는 것과 같습니다.
- 처음에는 "도메인 데이터로 학습시키면 판단 품질이 좋아질 것"이라고 생각했습니다.

## 2. 시도 — LoRA 파인튜닝

- 베이스: EXAONE, 방식: LoRA (원본 가중치는 고정하고 저랭크 행렬 `B·A`만 학습)
- 데이터: 운영 초기 **약 3주치** 판단 이력

## 3. 문제

| 관찰 | 의미 |
|---|---|
| 출력에 설명문이 섞이고 JSON 키가 빠지거나 바뀜 | **출력 형식 자체를 못 지킴** |
| 파싱 실패율 **80% 이상** | 판단 품질 이전에 시스템이 동작하지 않음 |

## 4. 원인 재정의

```
"데이터가 부족해서 학습이 덜 됐다" → 데이터를 더 모아 다시 학습?
   ↓ 멈추고 다시 정의
"소량 데이터 LoRA는 베이스 모델이 원래 잘하던 형식 준수 능력까지 흔든다"
   ↓ 그렇다면 비교 실험부터
같은 프롬프트로 파인튜닝 없는 베이스 모델들을 비교
```

| 구성 | 파싱 성공률 |
|---|---|
| EXAONE + LoRA (3주 데이터) | **20% 미만** |
| KANANA 1.5 8B (파인튜닝 없음) | **90% 이상** |

→ 결론: **파인튜닝보다 적절한 베이스 모델 선택이 더 중요할 수 있다.**

## 5. 해결 — 학습 대신 RAG

1. **베이스 모델 교체**: KANANA 1.5 8B를 파인튜닝 없이 사용
2. **매매 이력 RAG**: 37일치 plan(298종목 · 1,157건 판단 이력)을 저장해 두고, 현재 상황과 비슷한 과거 판단을 찾아 **few-shot 예시로 프롬프트에 주입**
3. **형식 방어**: 출력은 Pydantic 스키마로 검증하고, 앞뒤에 설명문이 붙은 경우 JSON 부분만 추출해 재검증

## 6. 결과

- 파싱 성공률 **20% 미만 → 90%+**
- 데이터가 쌓일수록 few-shot 예시의 질이 자동으로 좋아지는 구조 → **재학습 없이 개선**

## 7. 배운 점

- **"학습"은 기본값이 아니다.** 데이터가 적을 때는 학습이 기존 능력을 해칠 수 있습니다. 먼저 베이스 모델 비교, 다음 프롬프트·RAG, 마지막이 파인튜닝입니다.
- **가설은 비교 실험으로 확인한다.** "LoRA가 문제인가, 데이터가 문제인가"를 같은 조건의 베이스 모델 비교로 분리했습니다.
- 같은 방법(더 많은 학습)을 반복하기 전에 **원인을 다시 정의**했습니다. 이 습관은 이후 문서 AGENT의 재생성 → 템플릿 전환에서도 그대로 쓰였습니다.

---

## 예제 코드 — `fewshot_rag.py`

1) 과거 판단 이력에서 현재 상황과 비슷한 사례를 찾아 few-shot 프롬프트를 만들고,
2) "형식을 못 지키는 출력"과 "정상 출력"을 Pydantic 스키마로 검증해 파싱 성공률을 비교합니다. (LLM 출력은 예시 문자열)

```bash
pip install pydantic numpy
python fewshot_rag.py
```
