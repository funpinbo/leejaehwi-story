# 청중 맞춤 커리큘럼 설계 — 하나의 업무 예제로 모든 개념을 꿰기

> **한 줄 요약**: 개발자와 비개발자가 섞인 청중을 위해, 개념을 따로따로 설명하지 않고 **"우주 부품 PAD 작성"이라는 하나의 실제 업무**를 따라가며 AI 기본 개념 → 프롬프트 → Tool/Skill → 토큰 → 프로그래밍까지 이어지도록 설계했습니다.

---

## 1. 상황

- 사내 직원들은 LLM을 "검색창처럼" 한 줄 질문하고 답을 받는 정도로만 쓰고 있었습니다.
- 청중은 전 직원 — **기술 배경이 제각각**입니다.

## 2. 문제

| 문제 | 위험 |
|---|---|
| 개념 위주로 설명하면 | 비개발자는 "나와 무슨 상관인지" 모름 |
| 도구 사용법 위주로 설명하면 | 도구가 바뀌면 쓸모없어짐, "왜"를 모름 |
| 기법을 많이 나열하면 | 아무것도 기억에 안 남음 |

## 3. 설계 판단

1. **관통 예제 하나**: 모두가 아는 업무인 **PAD 작성**을 처음부터 끝까지 예제로 사용
2. **Hallucination을 원리로 설명**: "LLM은 지식을 꺼내는 게 아니라 다음 토큰을 확률적으로 예측한다" → 그래서 **지식(근거)은 넣어주고, 생각(절차)은 유도해야** 한다는 두 축으로 정리. 이 두 축이 Part 2(CoT = 생각), Part 3(Tool/RAG = 지식)로 자연스럽게 연결
3. **원 논문 인용**: Attention Is All You Need, CoT, ReAct, Toolformer 등 — 비개발자에게도 "근거가 있는 이야기"라는 신뢰
4. **토큰은 숫자로 보여주기**: "대화가 길어지면 비싸지고 느려진다"를 실제 계산으로 시연
5. 산출물은 마크다운 개요로 먼저 받아 직접 다듬고, **구어체 대본**도 직접 작성

## 4. 결과

- 세미나 실제 진행, 참석자 대부분이 "이런 방식으로 써본 적이 없다", "이제 제대로 활용할 수 있을 것 같다"는 반응
- 이후 사내에서 AI 관련 질문이 저에게 모이는 창구가 됨

## 5. 배운 점

- **청중의 업무에서 시작한다.** 개념은 업무를 설명하기 위한 도구일 때 기억에 남습니다.
- **원리를 알려주면 도구가 바뀌어도 남는다.** "확률적 다음 토큰 예측"이라는 원리 하나로 Hallucination, CoT, RAG의 필요성이 모두 설명됐습니다.
