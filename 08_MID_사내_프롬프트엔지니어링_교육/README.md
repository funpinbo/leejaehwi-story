# 08. MID · 사내 프롬프트 엔지니어링 교육 (세미나)

> 사내 직원 대부분이 LLM을 단순 질의응답으로만 쓰고 있어, **개발자와 비개발자가 섞인 전 직원**을 대상으로 AI 활용 세미나를 기획부터 대본까지 혼자 설계하고 진행했습니다.

| 항목 | 내용 |
|---|---|
| 형태 | 단독 기획 · 발표 |
| 청중 | 전 직원 (비개발자 비중 큼) |
| 관통 예제 | **우주 부품 PAD 작성** — 처음부터 끝까지 하나의 업무 예제로 설명 |
| 다룬 도구 · 개념 | Claude Code, Codex, Notion, MCP, Skill / Artifact, CoT, ReAct, Toolformer, FlashAttention 등 논문 인용 |

---

## 🗂️ 커리큘럼

| Part | 주제 | 핵심 |
|---|---|---|
| 1 | AI 기본 개념 | ML → DL → LSTM → Attention → LLM, Token / Embedding. Hallucination을 **"LLM은 지식을 DB처럼 꺼내는 게 아니라 다음 토큰을 확률적으로 예측한다"** 는 관점에서 "지식"과 "생각" 두 축으로 설명 |
| 2 | LLM 사용법 | Persona + **Chain-of-Thought**를 PAD 검토 절차로 직접 시연 |
| 3 | MCP / Tool / Skill | PAD 업무용 **Skill 3종**(ECSS 규격 확인 · 규격 버전 확인 · 문서 양식 확정)을 직접 설계해 제시, ReAct 논문과 연결 |
| 4 | Token / Context Window | 토큰을 쓰는 요소(질문 · System Prompt · Chat History · RAG 결과 · Tool 결과)와 절감 전략 |
| 5 | LLM 활용 프로그래밍 | 비개발자도 "코드를 짜려면 이렇게 접근하면 된다" 수준의 방향 제시 |

## 🎯 성과

- 전 직원 대상 세미나 커리큘럼 · 발표 자료 · 구어체 대본을 **단독으로 설계 · 제작해 실제 진행**
- AI 역사, 프롬프트 엔지니어링, LLM을 활용한 간단한 코드 작성을 직접 시연
- 참석자 대부분이 이런 방식의 LLM 활용을 처음 경험했고, **"이제 제대로 활용할 수 있을 것 같다"** 는 반응
