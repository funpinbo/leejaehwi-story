# 4계층 Atomic Block 스키마 — 불확실성과 근거를 스키마에 넣기

> **한 줄 요약**: 규격 문서를 `Document → Page(문단) → Group → Block` 4계층으로 나누고, Block 스키마에 **`confidence`(추출 신뢰도) · `requires_review`(사람 검토 필요) · `sources`(원본 PDF 영역까지 역추적)** 를 넣어, LLM 추출 결과를 그대로 믿지 않는 구조를 **설계 단계부터** 만들었습니다.

---

## 1. 상황

- PAD 작성에는 "이 부품군은 어떤 시험에서 어떤 문서를 참조해야 하는가" 같은 정보가 필요합니다.
- 이 정보는 규격 문서의 **조항 하나하나**와 그 조항이 **참조하는 다른 문서의 조항**에 흩어져 있습니다.

## 2. 문제

- 청크 단위로 자르면 "의미의 단위"와 "자르는 단위"가 어긋납니다.
- LLM으로 조항을 추출하면 **틀릴 수 있는데**, 틀린 추출이 그대로 그래프에 들어가면 이후 모든 답이 오염됩니다.

## 3. 설계 — 4계층

| 계층 | 정의 | 왜 필요한가 |
|---|---|---|
| **Document** | 규격 문서 1건 (번호 · Revision) | Revision 단위 관리 |
| **Page** | 실제 페이지가 아니라 **문단 단위** | PDF 페이지 경계는 의미와 무관 |
| **Group** | 표 · 그래프 · 이미지 · 목록처럼 **함께 관리돼야 하는 단위** | 표의 한 행만 떼면 의미가 없음 |
| **Block** | **의미의 최소 단위** (요구사항 1개, 정의 1개 …) | 참조 · 검색 · 검증의 기본 단위 |

Block이 다른(하위) 문서의 여러 Block을 참조할 수 있게 해서, 문서 집합 전체가 자연스럽게 **그래프**가 됩니다.
예: "A 파트는 시험 시 M 문서와 D 문서를 참조한다"를 하나의 관계로 표현.

## 4. 설계 — Block 스키마

| 필드 | 의미 | 설계 의도 |
|---|---|---|
| `block_id` | 문서 · 섹션 기반 고유 ID | 재추출해도 같은 Block은 같은 ID |
| `meaning_type` | REQUIREMENT / DEFINITION / NOTE … | 질문 유형별 필터 |
| `atomic_text` | **원문 그대로** | 법적 근거 — 절대 수정하지 않음 |
| `normalized_text` | 검색 · LLM용 **정규화 텍스트** | 문맥 보강은 여기에만 (→ 02의 리드인 주입) |
| `confidence` | 추출 신뢰도 0~1 | LLM 결과를 그대로 믿지 않음 |
| `requires_review` | 사람 검토 필요 플래그 | **Human-in-the-loop를 스키마 레벨에서 전제** |
| `section_path` | `5 > 5.2 > 5.2.1` | 문맥 · 계층 복원 |
| `sources` | evidence span, `source_region_id` | **원본 PDF 영역까지 역추적** |
| `references` | 참조하는 문서 · 조항 | 그래프 엣지의 원천 |

## 5. 결과

- ECSS-P-00 문서에서 **388개 Block** 실제 추출
- 신뢰도가 낮거나 참조 해석이 애매한 Block은 `requires_review=true`로 분리되어, **사람이 볼 것만 골라 볼 수 있게** 됨

## 6. 배운 점

- **불확실성은 나중에 처리하는 게 아니라 스키마에 넣는 것이다.** "LLM이 틀릴 수 있다"를 필드로 표현하자, 검토 흐름과 품질 지표가 자연스럽게 따라왔습니다.
- **원문과 가공본을 분리한다.** `atomic_text`(결정적, 불변)와 `normalized_text`(가공, 변경 가능)를 나눈 것은 06의 Content/Layout 분리와 같은 원칙입니다.
- **모든 값은 원본으로 돌아갈 수 있어야 한다.** 규격 도메인에서 "출처가 어디냐"에 답하지 못하는 데이터는 쓸 수 없습니다.

---

## 🧪 예제 코드 — `block_schema.py`

Pydantic으로 Block 스키마를 정의하고, **합성 규격 텍스트**(실제 ECSS 원문이 아님)를 Block으로 분해합니다.
참조 추출, 신뢰도 산정, `requires_review` 판정, `source_region_id`를 포함한 JSON을 출력합니다.

```bash
pip install pydantic
python block_schema.py
```
