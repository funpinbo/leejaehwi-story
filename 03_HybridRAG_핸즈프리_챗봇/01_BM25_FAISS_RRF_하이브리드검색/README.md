# BM25 + FAISS + RRF — 서로의 약점을 메우는 하이브리드 검색

> **한 줄 요약**: 벡터 검색은 장비 코드 같은 "정확히 같아야 하는 문자열"을 놓치고, BM25는 동의어·맥락을 놓쳐서 둘을 함께 쓰고, 점수 스케일이 다른 두 결과를 **순위 기반 RRF**로 합쳤습니다.

---

## 1. 상황

- 사내 문서에는 `EBR-3D-OPT-V2` 같은 **장비 코드**, 공정 약어, 한국어 복합명사가 많습니다.
- 질문은 음성(STT)으로 들어오므로 표현이 문서와 다를 수 있습니다.

## 2. 문제

| 검색 방식 | 잘하는 것 | 놓치는 것 |
|---|---|---|
| Vector (FAISS) | "의미가 비슷한" 문서 | 형태가 정확히 일치해야 하는 코드·약어 |
| BM25 (Elasticsearch) | 정확한 키워드 일치 | 동의어, 다른 표현 |

그리고 두 방식은 **점수 스케일이 완전히 달라서** 그냥 더할 수 없습니다.

## 3. 설계 판단

| 결정 | 이유 |
|---|---|
| **RRF** `score = Σ 1/(k + rank)` | 점수가 아니라 **순위**를 쓰므로 정규화가 필요 없음 |
| `k = 60` | 1위와 2위의 차이를 완충해 한쪽 검색이 순위를 독점하지 않게 함 |
| **Nori** 형태소 분석기 | "공정이상감지" → [공정, 이상, 감지]. 공백 토크나이징으로는 부분 검색 불가 |
| Nori **사용자 사전** | 장비 코드·약어는 쪼개지지 않도록 등록 |
| FAISS **IndexFlatL2** | 수만 건 규모라 완전 탐색 비용 허용. 근사 검색의 정확도 손실 없음 (수백만 건이면 IVF/HNSW) |

## 4. 결과

- 장비 코드 질의는 BM25가, 풀어 쓴 자연어 질의는 Vector가 상위로 끌어올리고, RRF가 둘 다 상위인 문서를 가장 위로 올렸습니다.
- STT 오인식이 있어도 Vector 검색이 보완 역할을 해서 검색 실패로 이어지는 경우가 줄었습니다.

## 5. 배운 점

- **한국어 RAG에서 하이브리드는 선택이 아니라 기본.** 한국어 임베딩 품질이 영어보다 불안정해, 형태소 분석만 잘 맞추면 안정적인 BM25가 바닥을 받쳐줍니다.
- **스케일이 다른 신호는 순위로 합친다.** 이 아이디어는 이후 여러 신호를 결합하는 설계에서 계속 썼습니다.
- 다음 단계로는 Top-20을 Cross-encoder(bge-reranker 등)로 재순위하는 2단계 구조를 적용하겠습니다.

---

## 🧪 예제 코드 — `hybrid_search.py`

외부 모델 없이 동작하도록 BM25는 직접 구현하고, Vector 검색은 **문자 n-gram 해싱 임베딩**으로 대체했습니다.
같은 질문에 대해 BM25 단독 / Vector 단독 / RRF 결합 순위를 나란히 보여줍니다.

```bash
python hybrid_search.py
```
