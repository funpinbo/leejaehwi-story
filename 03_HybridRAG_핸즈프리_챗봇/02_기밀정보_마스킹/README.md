# 기밀 정보 마스킹 — LLM에는 가리고, 사용자에게는 되살리기

> **한 줄 요약**: 사내 문서의 장비 코드·고객사·사람 정보가 외부 LLM으로 나가지 않도록 질문과 검색 컨텍스트를 **토큰으로 치환**하고, 답변이 돌아오면 사내에서만 원래 값으로 **복원**하는 가역 마스킹을 만들었습니다.

---

## 1. 상황

- 챗봇은 사내 문서를 검색해 LLM에게 컨텍스트로 넘깁니다.
- 문서에는 **고객사명, 장비 코드, 담당자 연락처** 같은 기밀이 섞여 있습니다.

## 2. 문제

| 요구 | 충돌 |
|---|---|
| 외부 LLM에 기밀이 나가면 안 됨 | 그냥 지우면 답변이 "어떤 장비"인지 알 수 없음 |
| 사용자는 정확한 장비 코드를 봐야 함 | LLM은 원래 값을 몰라야 함 |

## 3. 설계 판단

1. **치환, 삭제가 아님** — `EBR-3D-OPT-V2` → `[EQUIP_1]`. 같은 값은 항상 같은 토큰이 되므로 LLM이 문맥은 유지합니다.
2. **매핑 테이블은 사내에만** — 요청 단위로 생성, LLM 응답의 토큰을 원래 값으로 복원한 뒤 폐기.
3. **프롬프트 제약** — "마스킹된 토큰의 원래 값을 추측하거나 만들어내지 말라"는 경고를 시스템 프롬프트에 추가.
4. 그 외 Hallucination 대응: "컨텍스트에 없으면 '문서에서 찾을 수 없습니다'라고 답하라", Temperature 0.2.

## 4. 결과

- 기밀 원문이 외부 LLM 요청에 포함되지 않으면서도, 사용자에게는 정확한 장비 코드가 포함된 답변을 제공.

## 5. 배운 점

- **보안은 기능을 막는 게 아니라, 기능이 동작하는 경계를 정하는 것.** "무엇을 밖으로 보내지 않을지"를 먼저 정하니 구조가 단순해졌습니다.
- 정규식 기반 마스킹은 놓치는 패턴이 생기므로, 실제 운영이라면 NER 모델 + 사용자 사전 + 사람 검토를 병행해야 합니다. 이 고민은 이후 사내 챗봇 기획에서 **"보안 > 비용 > 1인 유지보수 > 성능"** 우선순위로 이어졌습니다.

---

## 🧪 예제 코드 — `masking.py`

정규식 + 사전 기반으로 마스킹하고, (가짜) LLM 응답의 토큰을 원래 값으로 복원합니다.

```bash
python masking.py
```
