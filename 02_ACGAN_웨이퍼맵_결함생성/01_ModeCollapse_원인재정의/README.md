# Mode Collapse — 방법이 아니라 구조를 바꾸다

> **한 줄 요약**: 하이퍼파라미터를 수십 번 바꿔도 Generator가 2~3종 패턴만 반복 생성했고, "판별자가 진짜/가짜만 판단한다"는 구조 자체가 원인이라고 다시 정의해 클래스 분류 과제를 가진 ACGAN으로 전환했습니다.

---

## 1. 상황

- WM-811K는 정상 웨이퍼가 약 78%이고, 결함 유형(Center, Edge-Ring, Scratch 등) 간에도 불균형이 심합니다.
- 소수 결함 클래스를 GAN으로 생성해 분류 모델의 학습 데이터를 보강하려 했습니다.

## 2. 문제 — Mode Collapse

- Generator가 **2~3종의 결함 패턴만 반복 생성**했습니다.
- 클래스 보강이 목적인데, 다양성이 없으면 데이터 보강 의미가 사라집니다.

## 3. 시도와 실패

| 시도 | 결과 |
|---|---|
| 학습률 · 배치 크기 조정 | 개선 없음 |
| Mini-batch Discrimination | 일시적 개선, 다시 수렴 |
| Spectral Normalization | 학습은 안정화, 다양성은 여전히 부족 |
| StyleGAN / CGAN / Stable Diffusion 탐색 | 데이터·연산 대비 과한 구조이거나 클래스 제어가 약함 |

**→ 수십 번의 실험 후 깨달은 것: "나는 같은 방법을 다른 설정으로 반복하고 있다."**

## 4. 원인 재정의

```
Mode Collapse가 왜 생기는가?
 → 판별자가 주는 신호가 "진짜/가짜" 하나뿐이다
 → Generator는 판별자를 속이는 몇 개의 패턴만 찾으면 손실이 줄어든다
 → 그렇다면 "어떤 클래스인지"까지 맞혀야 하는 신호를 추가하면 된다
 → ACGAN
```

## 5. 해결 — ACGAN의 손실 구조

```text
L_s = 진짜/가짜 판별 손실   (BCE)
L_c = 클래스 분류 손실      (Cross-Entropy, 진짜·가짜 이미지 모두)

Discriminator: L_s + L_c 를 잘 맞히도록 학습
Generator    : 진짜처럼 보이면서(L_s) + 요청한 클래스로 분류되도록(L_c) 학습
```

- "Scratch를 만들라"고 했는데 Center 같은 이미지를 만들면 `L_c`가 커집니다.
- Generator가 한 패턴으로 수렴하면 분류 손실이 커지므로, **구조적으로** 클래스별로 구별되는 이미지를 만들도록 강제됩니다.

## 6. 결과 및 검증

- 클래스별로 구별되는 결함 이미지 생성, Mode Collapse 해소
- 검증 원칙
  - **합성 이미지는 Train Set에만**, Test Set은 실제 이미지만 → Data Leakage 방지
  - FID로 분포 유사성 확인 + **결함 유형별 공간 패턴**(Edge-Ring은 가장자리, Center는 중앙)을 도메인 지식으로 육안 검증
  - 평가 지표는 전체 Accuracy보다 **소수 클래스 Recall** 개선 폭

## 7. 배운 점

- **"방법보다 원인 먼저."** 이 프로젝트에서 얻은 가장 큰 자산은 모델이 아니라 이 문제해결 습관입니다.
- **신호를 바꾸면 행동이 바뀐다.** 손실 함수는 모델에게 주는 유일한 피드백이고, 피드백이 단순하면 모델은 쉬운 길을 찾습니다. 이후 LLM 에이전트의 프롬프트·스키마 설계에서도 같은 관점으로 봅니다.

## 🧪 예제 코드 — `acgan_wafer.py`

3종(Center / Edge-Ring / Scratch)의 합성 웨이퍼맵을 만들고 작은 ACGAN을 학습합니다.
학습 후 **판별자의 보조 분류기가 생성 이미지를 요청한 클래스로 분류하는 비율**을 출력해, Generator가 클래스별로 구별되는 이미지를 만드는지 확인합니다. (CPU 약 20초)

```bash
pip install torch numpy
python acgan_wafer.py
```

실행 결과 (seed 고정):

```
클래스별 생성 이미지 분류 일치율 (Mode Collapse면 일부 클래스가 0%에 가까워짐)
  Center      97.0%
  Edge-Ring   96.5%
  Scratch    100.0%
  Center     클래스 내 다양성(평균 L2 거리) 11.14
  Edge-Ring  클래스 내 다양성(평균 L2 거리) 12.24
  Scratch    클래스 내 다양성(평균 L2 거리) 11.26
```

→ 세 클래스 모두 요청한 클래스로 분류되고(클래스 간 구별), 같은 클래스 안에서도 생성 이미지끼리 거리가 0이 아니므로(클래스 내 다양성) 한 패턴으로 수렴하지 않았음을 확인할 수 있습니다.

## 🎤 면접에서 이렇게 말한다
